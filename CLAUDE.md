# DISC Test — инструкции для Claude

Публичный мультиязычный тест DISC: https://disc-test.org/ (GitHub Pages, репозиторий `Man-You-Can/disc-test`, публикация из `main:/docs`). Заказчик общается по-русски.

## Перед началом работы
1. Прочитай `PROJECT.md` — описание проекта, текущее состояние, журнал работ и список открытых задач.
2. `README.md` — как собирать, менять тексты, добавлять языки, подключать отправку писем.
3. `SEO-AUDIT.md` — план продвижения: «Аудит 3» (2026-09-24, вечер) — перепроверка после правок и новые замечания, «Аудит 2» (2026-09-24) — основной план (ссылки, контент), «Аудит 1» — выполнен.
4. При работе над продажей расширенного отчёта — `private/SALES-PLAN.md` (план от 2026-10-09; вне git). Оплата в русской версии — эквайринг Т-Банка.
5. При работе над сервером, персональными данными, почтой или оплатой — `private/PRODUCTION-PLAN.md` (план перевода в боевой режим от 2026-10-09; вне git): свой сервер в России вместо Google Apps Script, Google Таблицы и GitHub Pages; там же вводные заказчика (налоговый режим, бюджет, решения).

6. При работе над персональными данными — `private/legal/` (вне git): `RKN-NOTIFICATION.md` — ответы для уведомления в Роскомнадзор, `INTERNAL-DOCS.md` — внутренние документы оператора.

## Правила
- Все тексты только в `src/locales/<язык>.json`; `ru.json` — эталон структуры. После любой правки локалей: `node scripts/validate-locale.js`.
- Сборка: `node build.js` → `docs/`. Публикация: закоммитить изменения вместе с `docs/` и запушить в `main`; GitHub Pages пересобирает за 1–2 минуты.
- `BLOCK_KEYS` в `src/template.html` не менять: от порядка зависят коды результатов, уже разосланные участникам.
- После каждого изменения проекта добавить датированную запись в `PROJECT.md` (раздел «Журнал работ») и при необходимости обновить «Текущее состояние» и «Что осталось». Коммитить вместе с изменением.
- Иконки и og-картинки: `node scripts/make-assets.js` (после смены `title` в локалях); шрифты: `node scripts/fetch-fonts.js` (только при смене набора шрифтов).
- Локальный просмотр: `node scripts/serve.js` (http://localhost:8765) или конфигурация `disc-static` в `.claude/launch.json`. У сервера есть заглушки `POST /mock-send` и `/mock-fail` для проверки отправки писем.
- `backend/apps-script/Code.gs` (собирается из `src/apps-script.template.js`) — ядро серверной части: тексты писем на 14 языках, расчёт, HTML краткого отчёта; свой сервер выполняет его же. После правки шаблона, текстов `email.*`, `content.extendedMail` или текста согласия — `node build.js`, `node scripts/test-apps-script.js`, затем выкладка на сервер: `bash private/server/deploy/deploy.sh` (иначе сервер шлёт прежние тексты).
- Бот в Telegram (справочный, только русский; отдельный проект Apps Script): шаблон `src/telegram-bot.template.js` → `backend/telegram-bot/Code.gs` при сборке; `node scripts/test-telegram-bot.js` проверяет его без Google и Telegram. Токен бота в репозиторий не попадает (свойства скрипта).
- Покупка расширенного отчёта на сайте (кнопка «Купить», страницы «Спасибо» и «Оплата не прошла», `src/pay.js`) включена 2026-10-12 в русской версии: ключ `"payEndpoint": "https://api.disc-test.org/pay"` в `site.config.json` — адрес сервера оплаты; без ключа сайт показывает заявку. Ключ и строка `PAY_MODE=live` на сервере меняются вместе: с ключом, но при выключенном сервере кнопка «Купить» отвечает ошибкой. Покупка появляется только в языках с `content.product.pay` в локали. Локальная проверка на заглушке — README → «Оплата расширенного отчёта (страницы сайта)».
- В PDF краткого отчёта и в теле письма с результатом с 2026-10-11 есть блок о расширенном отчёте (`"reportAd": true` в `site.config.json`) — во всех 14 языках. Форма русского блока утверждена заказчиком — тексты и раскладку без его слова не менять; в остальных языках блок строится по ней же, без листов образца, со строкой о заявке (`content.product.block.soon`) на их месте. После правки текстов блока — образцы PDF по 16 профилям языка: отчёт должен оставаться на двух листах (`private/samples/pdf-all.sh`, `pdf-check.py`). README → «Блок о расширенном отчёте в PDF краткого отчёта». В PDF не должно быть исходного кода результата и e-mail участника: PDF пересылают другим.
- Сервер оплаты (с 2026-10-11, `private/server/src/pay.js`, адреса `api.disc-test.org/pay/…`) работает в режиме `live` с 2026-10-12 (проверен на демо-терминале и настоящей покупкой с возвратом 2026-10-11): режим задаётся строкой `PAY_MODE=demo|live` в `/etc/disc/api.conf` на сервере, ключи терминалов вводит заказчик. Состояние и порядок проверки — `private/infra/SERVER.md`, раздел «Оплата расширенного отчёта». Цена, название услуги и письмо-напоминание о неоконченной оплате (`content.product.pay.remind`) берутся из этого репозитория: после их правки — сборка, `test-apps-script.js`, выкладка на сервер.
- Запасной почтовый канал (с 2026-10-11): при отказе основного почтового сервиса сервер шлёт письма через ящик `info@disc-test.org` у хостинга (`private/infra/SERVER.md`, раздел «Запасной почтовый канал»). Проверки, которым нужна служба без настоящих участников, — на второй копии службы (`PORT=<другой> NO_WORKERS=1`), а оплаты — `node test/pay-check.js` на сервере (подставной банк, писем не шлёт).
- С 2026-10-11 сайт работает через свой сервер: `"sendEndpoint": "https://api.disc-test.org/"` и `"pdConsent": true` в `site.config.json` (согласие на обработку персональных данных, страница согласия, новая редакция «Конфиденциальности»). Эти два ключа меняются только вместе: тексты описывают хранение данных в России. Скрипт Google заказчик заархивировал 2026-10-11: запасного пути через него больше нет, прежний адрес (`private/infra/old-send-endpoint.txt`) отвечает 404. После правки текста согласия или галочки менять `pdVersion` и выкладывать серверную часть. Аналитика: счётчик загружается сразу во всех языках (`"analyticsMode": "always"`, решение заказчика от 2026-10-11; режим «после согласия» не предлагать). README → «Аналитика по языкам, согласие на обработку данных и политика».
- С 2026-10-12 сайт считает все прохождения теста (`"profileStats": true` в `site.config.json`): в момент, когда тест пройден, страница шлёт серверу профиль и язык версии — без имени, e-mail, ответов и кода результата; сервер пишет их в таблицу `profile_stats` (день, язык, профиль), панель показывает на страницах «Профили» и «Прохождения» (счёт по дням). С вечера 2026-10-12 по кнопке «Начать тест» уходит вторая запись — только язык версии (таблица `test_starts`: день, язык; столбец «Начали тест» на «Прохождениях»); с записью о пройденном тесте она не связана. Ничего другого в эти запросы и в эти таблицы не добавлять: тексты о данных на 14 языках (`ui.privacy`, первый абзац раздела «Какие данные мы используем» в `content.policy`, `ui["pd.cookieDetails"]`, пункт 2.7 русской политики) описывают именно эти две записи. Ключ и эти тексты меняются только вместе. README → «Обезличенный счёт прохождений».
- Посетители сайта на странице «Прохождения» панели (с 2026-10-13): основная служба раз в час запрашивает у системы веб-аналитики готовое число посетителей по дням и языкам (`private/server/src/visitors.js`, таблица `site_visitors`) по ключу заказчика с правом «только чтение»; панель в сеть не ходит. Это чтение итоговых чисел, новых данных о посетителях сайт не собирает — тексты о данных не затрагиваются. Имя секрета, порядок проверки и замеченный обрыв данных в системе аналитики — `private/infra/SERVER.md`, раздел «Посетители из системы веб-аналитики на „Прохождениях“».
- В 13 нерусских версиях сайта страна хранения данных не называется нигде (решение заказчика от 2026-10-11): ни в политике, ни в согласии, ни в уведомлении о cookie, ни в письмах. О хранении в России говорит только русская версия.
- Хэш адреса с личными данными (`#r=…` — код результата, `#u=…` — ключ отписки) с 2026-10-13 убирается из адресной строки до загрузки счётчика веб-аналитики и хранится в `history.state` (`dataHash()` в `src/common.js`). В коде страниц читать его через `dataHash()`/`pageHash()`, не из `location.hash`; в разметку (адреса ссылок, атрибуты) не писать. `defer:true` у счётчика от передачи адреса не защищает: первый запрос уходит с полным адресом страницы. После правок кода счётчика, маршрутизации или ссылок с хэшем — проверка запросов на стенде `scripts/analytics-stand.js` (в сеть не выходит). README → «Аналитика».
- Наблюдение за доступностью — внешний сервис UptimeRobot в аккаунте заказчика: три проверки (сайт, `api.disc-test.org/health`, `admin.disc-test.org/health`); README → «Наблюдение за доступностью». Проверочный режим серверной части без писем (`MAIL_DRYRUN=1`) на работающем сервере больше не включать: адрес `/health` отвечает на него сбоем, а настоящие письма участникам в это время не уходят.
- Проверка перед публикацией: валидатор локалей, сборка, проверка внутренних ссылок (`node scripts/check-links.js`), просмотр в браузере.
- Платная услуга в 13 нерусских версиях (с 2026-10-11): страница отчёта, блок на экране результата, оферта, условия возврата и раздел о данных покупателя есть во всех языках, но вместо покупки — заявка: расширенный отчёт написан только по-русски. Ключи `content.product.pay` и `content.extendedMail` в нерусские локали не добавлять, пока отчёт на этом языке не написан: по первому при включённом `payEndpoint` появляется кнопка «Купить» и сервер оплаты принимает заказы. Срок появления отчёта на языке не называть нигде. Цена — 6,99 USD (`servicePriceUsd`) в записи, принятой в языке. Тексты на этих языках пишутся заново под местного читателя, а не переводятся с русского, и проходят отдельную вычитку редактором-носителем; юридические тексты держатся близко к русским. Порядок действий, когда отчёт на языке появится, — README → «Страницы „Услуги“, „Публичная оферта“ и „Условия возврата“».
- Оферта и условия возврата: русский текст — исходный, 13 остальных — переводы с оговоркой (`note`), что при расхождении действует исходный текст. В переводах нет слов «Россия», «российский» и ссылок на российские законы (решение заказчика от 2026-10-11). После правки русской оферты или условий возврата — та же правка в 13 переводах и новая дата в `content.offer.edition`.
- Заявки на расширенный отчёт приходят с формы обратной связи на `info@disc-test.org` с темой «Заявка на расширенный отчёт — <язык> (<код>): <имя>»; в панели администратора — столбец «Хочет расширенный отчёт» на странице «Результаты» и список заявок на странице «Согласия». Отвечает заказчик вручную.
- Расширенный отчёт (платная услуга): образец, исходник и правила — в `private/extended-report/` (папка вне git: в публичный репозиторий платный текст не попадает). Перед работой над отчётами прочитать `private/extended-report/EXTENDED-REPORT.md`; после каждой правки образца обновить этот файл в той же сессии (нужный раздел и «Историю правок»). Папка — отдельный git-репозиторий с закрытым хранилищем `Man-You-Can/disc-extended-report`: правки в ней коммитить и пушить оттуда же, отдельно от сайта. Отчёты собирает свой сервер (с 2026-10-10: очередь заданий, кнопка в панели администратора); сценарий GitHub «Собрать отчёт» — запасной. После правки шаблонов, блоков или сборщика — `python3 ci/layout-check.py make`, выкладка на сервер (`bash private/server/deploy/deploy.sh`) и сверка раскладки на сервере (раздел 14 правил).

- Свой сервер (с 2026-10-10): состояние, порядок входа и сделанные настройки — `private/infra/SERVER.md` (вне git); после каждого изменения на сервере обновлять этот файл в той же сессии. Секреты на сервер вписывает заказчик, в переписку и в файлы они не попадают.

Файл секретов `/etc/disc/secrets.env` — не файл команд оболочки: в сценариях его не читать через `.` или `source`, значения брать по именам и буквально, как `disc-env` (в значении может стоять `$`). `private/infra/SERVER.md`, раздел «Резервные копии».

## Что требует действий заказчика (нельзя сделать без его аккаунтов)
- Google Apps Script («Письма с lite-результатами») заархивирован заказчиком 2026-10-11 и больше не работает; бот в Telegram — отдельный проект Apps Script, он работает. Прежняя инструкция (историческая): развёрнут 2026-10-08. После правки `src/apps-script.template.js` или текстов `email.*`/`content.extendedMail`/отчёта — вставить новый `backend/apps-script/Code.gs` в редактор и выпустить новую версию развёртывания (README → «Письмо с результатом и база результатов»); URL не меняется.
- Отправка расширенного отчёта покупателю (сценарий «Собрать отчёт» → серверный скрипт → письмо): нужен один и тот же секрет в закрытом репозитории (`DELIVERY_SECRET`) и в свойствах скрипта (`extendedSecret`) и версия развёртывания с приёмом отчётов; проверка — `curl -sL -A "Mozilla/5.0" <sendEndpoint>` отвечает `"extended":true` (README → «Расширенный отчёт: письмо покупателю»). Секреты Claude записать не может — это делает заказчик.
- Рассылка: галочка согласия в форме отправки результата включена 2026-10-08 (`"newsletter": true` в `site.config.json`). Она требует версии скрипта с поддержкой рассылки: проверка — `curl -sL -A "Mozilla/5.0" <sendEndpoint>` отвечает `"newsletter":true` (без User-Agent Google отдаёт пустой ответ). Саму рассылку отправляет заказчик через сторонний сервис по строкам таблицы с «Рассылка» = «да» (README → «Рассылка: согласие и отписка»).
- Бот @disc_test_org_bot развёрнут 2026-10-03 (проект Apps Script «DISC — TG bot»). После смены цены, реквизитов или текстов бота — вставить новый `backend/telegram-bot/Code.gs`, выпустить новую версию развёртывания и снова выполнить `setup` (README → «Бот в Telegram»).
- Google Search Console, Яндекс Вебмастер, Bing Webmaster: подтвердить домен, отправить `https://disc-test.org/sitemap.xml`.
- Цели витрины расширенного отчёта в Метрике заведены 2026-10-09: семь целей типа «JavaScript-событие» — `ext-top`, `ext-anchor`, `ext-show`, `ext-click`, `ext-page-test`, `ext-page-order`, `ext-page-sample`. Новую цель в коде нужно заводить и в кабинете Метрики. Оплата на сайте включена 2026-10-12, а пять целей покупки в кабинете ещё не заведены — заказчик просил напомнить: `ext-page-buy`, `ext-pay-start`, `ext-pay-error`, `ext-pay-done`, `ext-pay-fail`. Заявки на расширенный отчёт из 13 нерусских версий приходят с формы обратной связи на `info@disc-test.org`: отвечать на них нужно вручную.
- Аналитика (Яндекс.Метрика или GA4); после подключения обновить тексты `consent.*` и страницу «Конфиденциальность» на 14 языках.
- Вычитка переводов носителями.
