## Правила
- Все тексты только в `src/locales/<язык>.json`; `ru.json` — эталон структуры. После любой правки локалей: `node scripts/validate-locale.js`.
- Сборка: `node build.js` → `docs/`. Публикация: закоммитить изменения вместе с `docs/` и запушить в `main`; GitHub Pages пересобирает за 1–2 минуты.
- `BLOCK_KEYS` в `src/template.html` не менять: от порядка зависят коды результатов, уже разосланные участникам.
- После каждого изменения проекта добавить датированную запись в `PROJECT.md` (раздел «Журнал работ») и при необходимости обновить «Текущее состояние» и «Что осталось». Коммитить вместе с изменением.
- Иконки и og-картинки: `node scripts/make-assets.js` (после смены `title` в локалях); шрифты: `node scripts/fetch-fonts.js` (только при смене набора шрифтов).
- Локальный просмотр: `node scripts/serve.js` (http://localhost:8765) или конфигурация `disc-static` в `.claude/launch.json`. У сервера есть заглушки `POST /mock-send` и `/mock-fail` для проверки отправки писем.
- `backend/apps-script/Code.gs` (собирается из `src/apps-script.template.js`) — ядро серверной части: тексты писем на 13 языках, расчёт, HTML краткого отчёта; свой сервер выполняет его же. После правки шаблона, текстов `email.*`, `content.extendedMail` или текста согласия — `node build.js`, `node scripts/test-apps-script.js`, затем выкладка на сервер: `bash private/server/deploy/deploy.sh` (иначе сервер шлёт прежние тексты).
- Бот в Telegram (справочный, только русский; отдельный проект Apps Script): шаблон `src/telegram-bot.template.js` → `backend/telegram-bot/Code.gs` при сборке; `node scripts/test-telegram-bot.js` проверяет его без Google и Telegram. Токен бота в репозиторий не попадает (свойства скрипта).
- Покупка расширенного отчёта на сайте (кнопка «Купить», страницы «Спасибо» и «Оплата не прошла», `src/pay.js`) включена 2026-10-12 в русской версии: ключ `"payEndpoint": "https://api.disc-test.org/pay"` в `site.config.json` — адрес сервера оплаты; без ключа сайт показывает заявку. Ключ и строка `PAY_MODE=live` на сервере меняются вместе: с ключом, но при выключенном сервере кнопка «Купить» отвечает ошибкой. Покупка появляется только в языках с `content.product.pay` в локали. Локальная проверка на заглушке — README → «Оплата расширенного отчёта (страницы сайта)».
- Покупка на экране результата и гарантия (с 2026-10-21): в языках с `content.product.pay` кнопки отчёта на экране результата раскрывают форму покупки на месте (`payForms` в `src/pay.js`, общий со страницей отчёта); строка `content.product.pay.guarantee` обязательна при `product.pay`. На витрине отчёт приходит «сразу после оплаты»; в оферте 24 часа — предельный срок (п. 4.2), гарантия возврата 7 дней без объяснения причин — п. 5.4 (редакция от 21 октября 2026 г.). На экране своего результата уведомление о cookie убирается (`window.discNoticeSeen`, только в режиме `always`). README → «Оплата расширенного отчёта (страницы сайта)».
- В PDF краткого отчёта и в теле письма с результатом с 2026-10-11 есть блок о расширенном отчёте (`"reportAd": true` в `site.config.json`) — во всех 13 языках. Форма русского блока утверждена заказчиком — тексты и раскладку без его слова не менять; в остальных языках блок строится по ней же, без листов образца, со строкой о заявке (`content.product.block.soon`) на их месте. После правки текстов блока — образцы PDF по 16 профилям языка: отчёт должен оставаться на двух листах (`private/samples/pdf-all.sh`, `pdf-check.py`). README → «Блок о расширенном отчёте в PDF краткого отчёта». В PDF не должно быть исходного кода результата и e-mail участника: PDF пересылают другим.
- **Что сделано для продажи в русской версии — во все языки вместе с покупкой** (правило заказчика от 2026-10-14). Всё, что делается для продажи расширенного отчёта в русской версии, применяется в каждой языковой версии в тот момент, когда в ней появляется покупка (`content.product.pay`): сейчас это личные зацепки, закреплённая кнопка и карточка вернувшегося посетителя (`content.product.promo`), письмо подписчикам о расширенном отчёте (`content.mailing.promo`, с 2026-10-25), дальше — любые новые правки витрины, покупки и писем. Поэтому: новый продающий элемент включается по ключу локали, а не по коду языка; его ключ дописывается в проверку валидатора «есть `product.pay` — должен быть и он» (так уже сделано для `product.promo` и `mailing.promo`) и в список README «Когда расширенный отчёт на языке будет написан»; тексты на языке пишутся заново и проходят вычитку носителем, как остальные тексты услуги.
- Страница «Как готовятся отчёты» (`content.howMade`, `ui["nav.howMade"]`; с 2026-10-14 во всех 13 языках, оба ключа обязательны) описывает то, как отчёты готовятся на самом деле: тексты заранее написал ИИ по правилам редакции, расчёт и сборку делает программа, шаблон каждого профиля редакция читает до продажи. При смене порядка подготовки отчётов (правила выбора блоков, участие ИИ в сборке, отправка, срок, цена, проверка человеком) текст правится во всех 13 языках сразу. Модель ИИ и её разработчик не называются нигде. Русский текст утверждён заказчиком; в 12 остальных языках о расширенном отчёте сказано как о заявке, без срока его появления, — при появлении покупки в языке (`content.product.pay`) эти места переписываются под покупку. README → «Страница „Как готовятся отчёты“».
- Доводка витрины там, где отчёт продаётся (с 2026-10-14; русская версия, с покупкой в английской, португальской, испанской, французской, немецкой, индонезийской, польской, турецкой, китайской и традиционной китайской — и они): закреплённая кнопка отчёта внизу экрана и карточка вернувшегося посетителя с личными зацепками на стартовом экране — по ключу `content.product.promo` (появляется только вместе с `product.pay` и обязателен при нём).
